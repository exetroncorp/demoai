02 — Fonctionnement

Comment fonctionne
un Agent IA ?

Un agent IA n'est pas un simple chatbot. C'est un système qui perçoit, raisonne, agit et apprend — en boucle autonome.

Percevoir

L'agent lit le code, les logs, les erreurs, les demandes en langage naturel — tout le contexte disponible.

Input

Raisonner

Chain-of-Thought, ReAct, Tree-of-Thoughts — l'agent décompose, planifie et choisit la meilleure stratégie.

Think

Agir

Écrire du code, exécuter des commandes, appeler des APIs, créer des fichiers — via des outils et des fonctions.

Execute

S'Améliorer

Vérifier les résultats, corriger les erreurs, affiner l'approche — la boucle se répète jusqu'à résolution.

Iterate
Boucle agentic — l'agent itère jusqu'à atteindre son objectif

Tool Use / Function Calling

L'agent peut invoquer des outils externes : terminal, git, APIs, bases de données, navigateur. Il décide quel outil utiliser et quand.

Mémoire & Contexte

Mémoire court-terme (conversation) et long-terme (projet, préférences). L'agent accumule de la compréhension au fil des interactions.

Guardrails & Validation

L'humain reste dans la boucle. Les agents opèrent dans des périmètres définis avec validation avant exécution critique.

05 — IBM Bob IDE

IBM Bob IDE
L'agentique en action

IBM Bob IDE est bien plus qu'un éditeur de code avec IA. C'est un environnement de développement agentique où l'IA est un collaborateur à part entière qui comprend votre projet, planifie des actions et les exécute de manière autonome.

Qu'est-ce que Bob IDE ?

IBM Bob IDE est un IDE de nouvelle génération développé par IBM, conçu nativement autour du paradigme agentique. Contrairement aux IDE traditionnels qui greffent un chatbot sur un éditeur, Bob est construit sur une architecture multi-agent où chaque agent est spécialisé dans un domaine.

Son nom « Bob » reflète l'idée d'un collègue de travail — pas un outil, mais un partenaire qui comprend le contexte, initie des actions et collabore activement.

IDE complet Multi-agent Cloud-native Enterprise-ready

Mission de Bob

Transformer le développeur en orchestrateur qui définit ses intentions pendant que les agents exécutent le travail lourd.

Différence clé

Les autres IDE ajoutent l'IA. Bob est né agentique. L'IA n'est pas un plugin — c'est le noyau de l'architecture.

Roots IBM

Hérite de décennies de R&D IBM : watsonx, Granite LLMs, l'écosystème Red Hat, et la sécurité enterprise.

Code Understanding

Analyse sémantique profonde du codebase entier, pas juste le fichier ouvert. Comprend les dépendances et les patterns.

Auto-Resolution

Multi-Agent Native

Human-in-the-Loop

06 — Architecture

Architecture interne
de Bob IDE

Bob n'est pas un chatbot greffé sur un éditeur. C'est une architecture distribuée où les agents communiquent via un bus d'orchestration central.

Vue d'architecture

Développeur
Bob Orchestrator

Planification, routage, coordination

Code Agent

Génération, édition, refactoring

Debug Agent

Analyse, root cause, fix

Test Agent

Génération, exécution, coverage

Doc Agent

Documentation, commentaires, README

Tool Layer Terminal · Git · File System · Linter · Compiler · Browser · APIs
IBM Granite / watsonx

LLM backend + embeddings

Bus de messages

Les agents communiquent via un bus d'événements asynchrone. Le Code Agent peut demander au Test Agent de vérifier un changement en temps réel.

Shared Context Store

Un store de contexte partagé permet à chaque agent d'accéder à l'état du projet : fichiers ouverts, erreurs récentes, historique des actions.

Permission Layer

Chaque action d'un agent passe par une couche de permissions. Les opérations destructrices nécessitent une approbation humaine explicite.
